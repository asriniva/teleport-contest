## Current status: shadow capture and real terminfo


The user explicitly requested shadow capture and removal of the terminfo-to-ANSI
shortcut. The adapter now defaults to **shadow**. `TELEPORT_TERMINAL=ghostty`
retains the earlier emulator only as an explicit diagnostic option; the ordinary
setup/test path no longer downloads or tests Ghostty. The ANSI replacements
W01/W02/W05/W06 and A04's stub tputs/ospeed have been removed from the build.
NetHack's original TERMINFO/TERMLIB definitions and terminal-capability code are
retained. **Current result after Q01–Q04 and 49 configured JS ports through dbridge, with JS date data (J01–J55):
44/44 public sessions, 11,405/11,405
screens and cursors, 792,838/792,838 RNG calls and 1,483/1,483 animation frames;
no runtime errors.** Native terminfo comparison, recorder encoding, codec
interoperability/error handling, save/restore/bones, profile overrides,
timezone/season and macOS checks pass. These public results do not establish
all hidden-case, browser or arbitrary-environment behavior.

The previous default Ghostty+ANSI build passed 0/44 sessions, 644/11,405 screens.
The earlier shadow+ANSI build passed 22/44, 10,343/11,405 screens. Both used the
agent's ANSI shortcut, introduced to bypass the native dependency. That shortcut
was not user-requested, was not necessary for Wasm, and was inadequately explained.
It must not be described as a faithful adaptation of the recording environment.

### What is known and what is not

The documented reference uses macOS, TERM=xterm-256color, 80×24, New York time.
The re-recording script says original sessions used tmux; supplied reproduction
code uses an internal shadow grid. Shadow tracks characters, foreground colors,
bold/inverse/underline and DEC graphics, with no independent background field.
These representation limits have not been shown to explain all prior failures.
A confirmed Ghostty+ANSI mismatch was bright white in the shadow/reference versus
bold normal white from actual stdout; this was not a whitespace diagnosis.
Remaining failures need individual investigation, not blanket attribution to
shadow capture or an emulator. The user has not authorized changes to the frozen
harness; none are included here.

### Third TU: strutil.c (J06, validated)

`js/ported/strutil.js` preserves all nine original functions, their parameters,
names and original comments. It uses byte-addressed C memory, signed char
reads and unsigned byte writes, rather than JS strings or regular expressions.

labelled infinite loop/continue because JS has no goto. C pointers are numeric
addresses and int casts use signed 32-bit coercion. The inline buffer size,
struct layout and LARGEST_INT come from the matching Clang-built C probe.

`c-runtime.js` scopes synchronous dependencies around each ABI call and restores
the preceding scope on return or exception/longjmp. This avoids sharing one
game's C memory with another game. The bindings in `wasm-runtime.js` and
`tu-library.js` access the current heap after every possible C allocation;
strbuf fields stay in the original C struct. C libc strlen/strcpy/strcat/strchr,
NetHack alloc/free and lowc remain C dependencies; MONITOR_HEAP is not enabled
in this configuration. `tu-support.c` is a narrow ABI shim for the original
variadic panic call so Clang, rather than JS, constructs its varargs. It does
not replace panic's behavior or add game logic. The build compiles and links
this shim with the same game flags. Pure JS conversion is still incomplete.

`tu-strutil-probe.c`, the extended `build-tu-probes.py`/`write-tu-layouts.mjs`,
and `test-tu-strutil.mjs` compare original C and C-caller/JS builds for buffer
content and capacity, allocation transitions, CRLF handling, byte/case-sensitive
wildcard matching, the 32767-byte length guard, independent contexts and heap
growth inside an allocation callback. 8,352 comparisons passed. Both probes
link the original C alloc.c/hacklib.c dependencies; only their isolated panic
records its formatted message and longjmps back to the test. Production still
calls NetHack's actual panic. This also verifies that the dependency scope is

### Per-TU ABI library isolation (J10)

Replace the monolithic `nethack-c/wasm/tu-library.js` with
`nethack-c/wasm/tu-libraries/<tu>.js`, preserving each declaration/helper body.
